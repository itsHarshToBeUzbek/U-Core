# U-Core — техническая документация

Расширение Chrome (Manifest V3) для пункта выдачи Uzum ТАШ-120 и FrТАШ-223.
Работает поверх WMS на `dp.uzum.uz`, данные берёт из `api-wms.uzum.uz`.

Версия на момент написания — 2.16.1. Актуальная всегда в `manifest.json`.

---

## 1. Главный принцип

**Данные попадают в расширение только тогда, когда их попросил человек** —
кнопкой сбора или импортом CSV. Всё остальное из этого следует.

Так было не всегда. Первые версии подслушивали трафик страницы: копировали
каждый ответ WMS, разбирали его наугад, вели «каталог подсмотренных
шаблонов», подчищали DOM. В таблицу приёмки попадал мусор — обрывки строк
без заказа, — и каждая новая заплатка порождала следующую. Всё это удалено;
перечень удалённого и причины — в `ARCHITECTURE.md`, раздел «Чего здесь
намеренно НЕТ».

## 2. Как ходят данные

```
                      ┌──────────────────────────┐
   оператор  ──нажал──▶  popup / priemka.html    │
                      └───────────┬──────────────┘
                                  │ ucore:sync-all
                                  ▼
                      ┌──────────────────────────┐
                      │  background.js           │  шесть независимых шагов
                      └───────────┬──────────────┘
                                  │ просит выполнить GET
                                  ▼
                      ┌──────────────────────────┐
                      │  wms-harvester.js        │  MAIN-мир страницы WMS
                      └───────────┬──────────────┘
                                  │ ответ как есть
                                  ▼
                      ┌──────────────────────────┐
                      │  wms-parse.js            │  явные мапперы
                      └───────────┬──────────────┘
                                  ▼
                         chrome.storage.local
```

Запрос выполняет **страница**, а не расширение. У страницы живая сессия и
свежий токен по построению. Попытки воспроизвести авторизацию своими
силами каждый раз кончались 401 при полностью работающем WMS — подробности
в `WMS-API-NOTES.md` §1.

## 3. Файлы

### Ядро

| Файл | За что отвечает |
|---|---|
| `manifest.json` | MV3. Права: `storage`, `activeTab`, `scripting`, `tabs`. Хосты — только `dp.uzum.uz` и `api-wms.uzum.uz`; адреса переводчика — в `optional_host_permissions`, то есть их нет, пока человек не включил перевод |
| `wms-harvester.js` | MAIN-мир, `document_start`. Два дела: запомнить заголовок `Authorization`, который ставит сама страница, и выполнить GET по просьбе расширения. Ответы страницы не читает |
| `content.js` | Инъекция в `dp.uzum.uz`. Инкассация (независимый блок), мост к харвестеру, два факта из трафика: адрес API и ключ ПВЗ. Плюс имя оператора из левого нижнего угла — короткое для акта инкассации, полное для АПП и диагностики |
| `wms-api.js` | Известные адреса WMS, постраничное чтение, пул запросов, повторы. Единственный разрешённый POST — справочник товаров |
| `wms-parse.js` | Явные мапперы под известные формы ответов, ключ записи, слияние, сверка «что исчезло», `shelfState` |
| `background.js` | Сервис-воркер. Сбор в шесть независимых шагов, каждый переживает отказ соседа |
| `allocation-core.js` | Логика раскладки по ячейкам. Чистый ES-модуль: ни `chrome.*`, ни DOM — гоняется под Node |
| `sku-name.js` | Словарь названий, разбор количества и цвета, оценка веса, проверка чужого перевода. Классический скрипт: подключается и тегом, и импортом в service worker |
| `name-llm.js` | Перевод названий моделью: OpenAI-совместимый транспорт, пачки, сверка пачки, очередь |
| `wms-csv.js` | Разбор выгрузки «Скачать .csv» |
| `pvz-config.json` | Конфигурация ПВЗ: структура ячеек, пороги, разметка зала |
| `fonts.css` + `fonts/` | Manrope и JetBrains Mono, лежащие рядом. Раньше подключались с fonts.googleapis.com — см. §5.1 |

## 4. Бланки: как это сделано

Все четыре бланка рисуются **в SVG**, а не в HTML. Причина: в SVG
координата текста — это и есть базовая линия. В HTML базовую линию
приходится выводить из метрик шрифта, а Chrome округляет высоту строки до
целых пикселей по-разному для разных кеглей, и лист уезжает на полтора
пункта.

Что проверено измерением и зафиксировано:

- **Поля `<body>`.** `@page { margin: 0 }` обнуляет поля страницы, но не
  поля тела. Восемь пикселей по умолчанию сдвигают лист на 6 пунктов и
  заставляют Chrome ужать его, чтобы влез. В стиле каждого бланка стоит
  `html, body { margin: 0 }`.
- **Кернинг.** У АПП его надо выключить (Word набирает бланк без него), у
  диагностики — оставить. Установлено сравнением с образцом попиксельно,
  не угадано.
- **`text-rendering: geometricPrecision`.** Нужен там, где строки длинные
  и должны сходиться с линейками бланка: без него Chrome округляет ширину
  каждой буквы до целого пикселя принтера, и к концу строки набегает
  пункт-полтора.
- **Масштаб печати.** Chrome не даёт API к полю «Копии» и ползунку
  масштаба в окне печати. Поэтому 70 % акта инкассации вшиты в сам лист
  через `transform: scale(.7)`, а N копий — это N страниц.
- **Тонкие линии не печатаются.** Обводка 0.6 pt при масштабе 0.7 даёт
  0.15 мм — меньше того, что лазерный принтер уверенно кладёт тонером. Вся
  сетка нарисована залитыми прямоугольниками.

Совпадение с образцами, замер при 300 dpi: АПП — 99.6 % чернил в пределах
одного пикселя; диагностика — 97.8 % в пределах двух (остаток на счёт
подменного шрифта в тестовом контейнере: там Liberation Sans вместо Arial).

## 4.1. Шрифты лежат рядом, а не у Google

`popup.html`, `inventory.html` и `layout.html` подключали Manrope и
JetBrains Mono ссылкой на `fonts.googleapis.com`. Это ломало сразу две
вещи.

Обещание. И этот документ, и документ оператора говорят, что до включения
перевода названий расширение не обращается ни к одному сервису. Обещание
было неправдой: каждое открытие попапа уходило запросом к Google, и вместе
с ним туда уходили адрес ПВЗ, время и строка браузера. Ни заказов, ни
клиентов в этом запросе нет — но и самого запроса быть не должно.

Скорость. Пока стиль не загрузился, Chrome держит отрисовку. На медленном
интернете попап открывался в системном шрифте или с задержкой, а ловил её
оператор ровно тогда, когда у него в руках коробка.

Теперь `fonts.css` и папка `fonts/` лежат в расширении: 36 файлов,
подмножества `latin`, `latin-ext`, `cyrillic`, `cyrillic-ext`. Греческое и
вьетнамское выброшены — на ПВЗ их не бывает. Проверка не на глаз: страницы
открываются в живом Chromium с перехватом сети, и ни одна не делает ни
одного запроса наружу.

Ко всему, что рисуется ПОВЕРХ страницы WMS (`placement.js`, `content.js`),
это не относится: там шрифт `inherit` и системный, чужие файлы туда не
подключаются.

## 5. Хранилище

Всё в `chrome.storage.local`. Наружу из этого не уходит ничего, кроме
названий товаров, и только при включённом переводе — см. §6.

| Ключ | Что лежит |
|---|---|
| `priemkaRecords` | полка: заказы и позиции с ячейками |
| `priemkaCells` | справочник ячеек WMS |
| `priemkaSku` | названия и габариты товаров |
| `skuNameCache` | готовые переводы: ШК → `{text, src, by, at}` |
| `skuNameLlm` | настройки перевода: сервис, адрес, модель, размер пачки |
| `skuNameKey` | ключ сервиса. ОТДЕЛЬНЫМ ключом: настройки уходят в отчёты и в интерфейс, ключ — никогда |
| `skuNameRun` | ход текущего перевода, его читает панель |
| `priemkaFbsContents` | составы посылок из описи WMS |
| `priemkaSync` | ход последнего сбора: шаги, ошибки, полнота |
| `priemkaInventory` | сессия обхода: найдено, недостача, лишнее, по ячейкам |
| `priemkaInvJournal` | журнал сканов обхода |
| `pvzLayout` | ручная разметка зала |
| `savedCounts`, `savedEncashCounts`, `savedBagNumber`, `savedBagAt` | касса |
| `encashActConstants` | реквизиты акта инкассации |
| `appDraft`, `appPrinted` | черновик АПП и последний напечатанный |
| `diagDraft`, `diagPrinted` | то же для диагностики |
| `wmsUserName`, `wmsUserFullName` | имя оператора из WMS: короткое и полное |

Хранилище у расширения одно на всё — 10 МБ. Проект уже терял живые заказы
из-за переполнения, поэтому пределы стоят заранее: история чистится каждым
сбором (старше 21 дня, не больше 3000 записей), составы посылок обрезаются
по 2000, и **история никогда не вытесняет полку**.

## 6. Названия товаров: два источника и две проверки между ними

Показать оператору название — это два файла, и разделены они не по слоям, а
по тому, кому можно верить.

`sku-name.js` — словарь и правила: 62 главных слова, узбекско-русские пары с
родом и плотностью, разбор количества и цвета, оценка веса. Работает всегда,
без сети и без ключа. **Полным он не будет никогда**, и это не недоделка:
список того, что человек может заказать, не закрыт. И число «54 узнанных из
55» нечестное — оно получено на тех же названиях, по которым словарь и
составлялся.

`name-llm.js` — модель. Транспорт один, OpenAI-совместимый
`/chat/completions`, поэтому Gemini, OpenAI, DeepSeek, OpenRouter и местная
Ollama — это одна и та же функция с разным адресом. Адрес нельзя сделать
просто полем ввода: Chrome разрешает спрашивать право только на хосты из
манифеста, и новый сервис — это строка в `optional_host_permissions`. Так и
надо: расширение не должно уметь отправить названия куда попало.

**Что уходит наружу.** Только `name` из `priemkaSku`. Это видно прямо в
`pendingNames()`: другого источника у списка на отправку нет, записи о полке
(клиент, телефон, заказ, ячейка) в него не попадают вовсе.

**Ключ.** В `skuNameKey`, отдельно от настроек, потому что настройки уходят в
`nameStatus()` и дальше в интерфейс. Наружу ключ уходит одним путём —
заголовком `Authorization` на выбранный адрес. В подсказку он не попадает: её
текст оседает в журналах сервиса.

**Почему пачками.** Подсказка с правилами и примерами весит втрое больше
самого названия. Спрашивать по одному — платить за правила столько раз,
сколько товаров. Двадцать пять названий в запросе стоят немногим больше
одного; весь справочник ПВЗ — около двадцати запросов и пара центов.

**Две проверки, и они про разное.**

`checkTranslation` (в `sku-name.js`) смотрит на сам перевод. Правило одно: **в
ответе не должно появиться ничего, чего не было в исходном названии.** Каждое
число ответа обязано стоять в оригинале, каждое латинское слово — тоже. Плюс:
одна строка, по-русски, не длиннее 70 знаков, не эхо вопроса, без `<think>` и
«Перевод:». Потерянное количество дописывается из оригинала — оно написано
цифрами и читается точно.

`alignBatch` (в `name-llm.js`) смотрит, **тому ли товару достался ответ**. Это
опасность именно пачки: модель вернёт двадцать четыре ответа вместо двадцати
пяти или сдвинет их на один, и правильный перевод встанет к чужому товару.
Глазами такую ошибку не видно — название читается нормально. Поэтому модель
обязана в каждом ответе повторить первые два слова оригинала (`"o"`), и мы
сверяем. Не совпало — ответ выброшен, товар остался в очереди.

Номеру `i` от модели одного доверия мало именно поэтому: сдвиг на единицу
выглядит как исправно работающая программа.

**Очередь** (`translateAll` + `startNameRun` в `background.js`): пачка за
пачкой, сохранение после каждой, остановка по кнопке и сама — после трёх
отказов подряд. Пачка, ответ которой не разобрался, делится пополам до
одного товара: терять двадцать четыре готовых перевода из-за одного
неудачного названия незачем.

**Чего стоило не проверять транспорт заглушкой.** В `test-names-llm.mjs`
поднимается настоящий http-сервер на 127.0.0.1, отвечающий как
OpenAI-совместимый сервис. На нём нашлось то, чего заглушка не показала бы:
ключ с русской буквой (или с переводом строки на конце) заставлял браузер
отказаться собирать запрос, а наружу это выходило как «не удалось
соединиться» — и человек проверял бы интернет, роутер и адрес сервиса, всё,
кроме единственного места, где ошибка. Теперь ключ проверяется до запроса
(`keyProblem`), а TypeError без `cause` больше не выдаёт себя за обрыв связи.

## 7. Тесты

### Что есть сейчас

```
sh tests/run-all.sh                              весь набор            130
```

| Набор | Что проверяет | Проверок |
|---|---|---|
| `tests/test-parse.mjs` | разбор, ключ записи, слияние, сверка | 24 |
| `tests/test-names.mjs` | строение названия, словарь, вес | 40 |
| `tests/test-names-llm.mjs` | перевод моделью, против живого http-сервера | 31 |
| `tests/test-pages.py` | восемь страниц в настоящем Chromium | 35 |

Отдельно, не тест, а замер: `node tests/measure-names.mjs <выгрузка>` считает
по живой выгрузке приёмки, скольким названиям срезан хвост, сколько узнал
словарь и скольким удалось назвать вес.

Каждая проверка испытана «наоборот»: баг возвращали в код и убеждались, что
она падает И НАЗЫВАЕТ ПРИЧИНУ СЛОВАМИ. Проверка, которая не падала ни разу,
не охраняет ничего.

### Чего НЕТ

Набор, описанный в прежней редакции этого документа, в репозиторий никогда
не попадал: `test-allocation.mjs` (43 проверки на логику раскладки),
мок-сервер WMS и 21 файл сквозных тестов, около 815 проверок. Их нет ни в
одном коммите — только в архивах на машине разработчика, если они там
сохранились.

Значит, **логика раскладки и весь сбор данных из WMS сейчас не покрыты
ничем**. Это не «мало тестов», это отсутствие тестов у двух самых дорогих
частей: именно они теряли по полсотни заказов и прятали недостачу.

Каким должен быть мок, когда его будут писать: он обязан повторять **живую**
систему вместе с её поломками. По части заказов WMS стабильно отвечает
пятисоткой — 27 % на замере 30.08.2026, — и мок это воспроизводил. Мок,
повторяющий догадку вместо реальности, — такая же ошибка, как зашитый домен.

Каждая проверка испытана «наоборот»: баг возвращали в код и убеждались,
что тест падает.

Чего стоило не проверять страницы глазами. Страница, у которой не подключился
модуль, выглядит целой — разметка на месте, — а JS к ней не подключён, и
наружу это выходит не ошибкой, а тем, что ничего не нажимается: восемнадцать
тестов упали именно так, и час ушёл на причину. У service worker то же самое
грубее — без модуля он не стартует вовсе. Поэтому `tests/test-pages.py`
поднимает все восемь страниц и жмёт каждую вкладку попапа.

Там же проверяется главное обещание расширения: ни одна страница не делает
ни одного запроса наружу. Ровно этой проверки не хватало, когда три страницы
тянули шрифты у Google (см. 2.16.1).

## 9. Правила, которые нельзя нарушать

Их 47, каждое появилось после поломки, и каждое объясняет, после какой
именно. Полный список — в `ARCHITECTURE.md`. Самые дорогие:

1. **Только GET.** Единственное исключение — `POST /de/sku/basic/all/id`
   (справочник товаров). Список изменяющих адресов отсекается регуляркой в
   двух местах: в расширении и на стороне страницы.
2. **Кнопки в WMS жмёт только человек.** Расширение не кликает ничего.
3. **Домен не зашивается в код.** Хосты — в `manifest.json`, адрес API —
   из трафика, границы — из `chrome.runtime.getManifest()`. Литерал
   `uzum.uz` в исходниках считается багом: так этот проект ломался пять
   раз подряд, причём молча.
4. **Сверка «что исчезло» — только по дочитанному списку.** Если список
   оборвался на середине, а сверка всё равно отработает, она пометит
   выданными сотни заказов, которые просто не успели прочитаться.
5. **Строка списка ≠ заказ.** У потоварной выдачи один заказ приходит
   несколькими строками с общим `b2cOrderId`. Ключ разводит их по
   внутреннему номеру отправления.
6. **Ячейка — не доказательство.** Выданный заказ ячейку не теряет: WMS
   помнит, где он лежал. Найденным на обходе считается только то, что по
   данным WMS лежит на полке.
7. **Обрыв связи и пятисотка — это «повторите скан», а не «товара нет».**

## 10. Что не доделано

- **`sectionSeverityOrder` в `pvz-config.json`** — секции перечислены по
  номеру, а не по реальной досягаемости. Это единственное, что нельзя
  снять из API: нужен обход зала с замером. Пока порядок номерной,
  рекомендации раскладки настроены не до конца.
- **Вкладка «ИИ Регламент»** — заглушка. Задумана как справочник правил и
  опыта сотрудников ПВЗ с подсказками во время работы.
- **`PROJECT-OVERVIEW.md`** устарел: он описывает версию 1.3.0 и тот самый
  перехват трафика, которого больше нет. Читать его как описание текущего
  состояния нельзя.
- **Модель не выбрана и ни одна не замерена.** Код готов и проверен, но
  какая модель справляется с узбекским — неизвестно. Мерить надо не «нравится
  ли перевод», а долю ответов, отклонённых проверками, на живом справочнике:
  это число, и оно видно в панели. Там же видно, чем именно они отклонены —
  «придумано число» и «ответ не про этот товар» означают разные беды.
- **Настоящая полнота словаря неизвестна.** 54 из 55 — это замер на том же
  срезе, по которому словарь составлялся. Нужна свежая выгрузка названий с
  новой поставки, и только она скажет, насколько перевод моделью вообще
  нужен.
- **Тексты в интерфейсе** написаны с помощью ИИ и местами это заметно:
  встречаются пояснения, адресованные разработчику, а не оператору, и
  утверждения о рабочих процессах, которые никто не проверял. Нужен проход
  по всем видимым строкам.
